Code-enforced transitions · LLM proposes, state machine disposes · Yellow = live, blocked on human/external  —  MAF 1.0 (GA Apr 2026) built on Semantic Kernel 1.x · SK is the documented 1-yr fallback (Apr 2026 – Apr 2027)
What ASCRA eliminates
✓Manual login across 6 tools per renewal
✓CSR on local machines — private key exposure risk
✓Manual Jira ticket creation and CSR attachment
✓Manual PKI email form composition and dispatch
✓Manual X.509 verification (error-prone)
✓Manual ServiceNow change ticket creation
✓Incomplete audit — full hash-chained log per tool call
✓Serial bottleneck — up to 100+ concurrent batch renewals
What ASCRA does NOT change
⚠PKI team SLA — still 0–5 business days (external)
⚠PD decision time — 0–48 h; ASCRA adds deadline + escalation
⚠Certificate deployment to the endpoint (v1 out of scope)
⚠CAB process for wildcard certs (G6 enforces this)
⚠PKI team workload or resourcing
⚠Total calendar time = automated steps (<15 min) + human / external wait time
8 Guardrails — all release blockers
G1Never skip PD approval — state machine enforced
G2Reject CN / SAN mismatch — deterministic, not LLM
G3Halt + escalate after 2 consecutive tool errors
G4One structured audit entry per tool call
G5All MCP output is untrusted data — never instructions
G6Block wildcard CSRs — mandatory CAB routing
G7Private keys non-exportable, never leave HSM
G8No secrets in code — Managed Identity + Key Vault only
